# [시스템 전수조사 및 5대 극한 케이스 자가 검증 절대 통제 규정]

1. [5대 취약 경계 케이스 전수 테스트셋 구성 의무화 복분]
사주 연산 엔진, 백세인생 창고, 리포트 생성기 등 어떠한 시스템 모듈을 점검하거나 수정할 때,
임의의 예시 1~2개만 돌려보고 '정상 작동한다'고 정성적으로 보고하는 행위를 엄격히 금지하며,
반드시 다음 5대 취약 경계 케이스를 포함한 최소 10개 이상의 전수 검증 매트릭스를 시스템 내에 자동 구성하여 실제 연산을 일괄 구동해야 한다:
  ① [음력 평달 케이스]: 음력이 실제 양력 절기 월(月)로 오차 없이 환산되는지 검증
  ② [음력 윤달 케이스]: 윤달 플래그가 누락되지 않고 해당 연도의 윤달 일수로 정밀 환산되는지 검증
  ③ [자시(23:00~00:59) 경계 케이스]: 날짜 변경선에서 일주와 시주가 왜곡되지 않는지 검증
  ④ [24절기 교입 당일 케이스]: 절기 시각 전/후 1분 차이로 월주가 정확히 교체되는지 검증
  ⑤ [남/녀 순역(順逆) 대운 케이스]: 양남음녀(순행)와 음남양녀(역행)의 대운수 및 간지 진행이 일치하는지 검증

2. [이중 파이프라인 기계적 Diff 전수 대조 복분]
전수 테스트셋을 구동할 때에는,
기존 마보살 정규 엔진(`MabosalIntegratedService`)과 신규 구축된 백세인생 창고(`LifeAnalysisWarehouseBuilder`) 양쪽에 동일한 입력 파라미터를 동시에 주입한 후,
산출된 [4주 8글자, 공망, 대운수, 10개 대운 간지, 현재 대운 순번]을 1:1로 기계적 필드 대조(Diff)하여 단 1글자 또는 1숫자의 불일치라도 존재하는지 자가 전수 탐색을 완료해야 한다.

3. [무결성 입증 매트릭스 표 제출 전 답변 및 완료 선언 금지 복분]
작업 완료를 사용자에게 보고하거나 답변을 작성하기 전에는,
상기 전수조사 실행 결과(테스트 케이스 번호, 테스트 유형, 정규 엔진 결과, 백세인생 결과, 불일치 여부, 판정 PASS/FAIL)가 일목요연하게 정리된 [전수조사 검증 매트릭스 표]를 답변 서두에 반드시 첨부하여 '오차 0건(Zero-Defect)'을 직접 입증해야 하며,
만약 단 하나의 케이스라도 FAIL(불일치)이 발생하는 경우에는 '완료되었다'는 표현을 일체 사용할 수 없고 즉시 원인 규명 및 자가 수정 절차로 회귀해야 한다.

4. [우회 파이프라인 영구 결함 판정 및 통합 복분]
전수조사 과정에서 하위 모듈이 정규 파이프라인을 건너뛰고 독자 연산을 수행하여 불일치를 유발한 사실이 확인된 경우,
이를 부분적인 단순 누락으로 축소 보고하지 말고 '시스템 아키텍처 결함'으로 규정하여,
기존에 검증된 마보살의 공인 표준화 레이어와 완전히 단일화(SSOT)되도록 파이프라인을 전면 직결하는 근본 수정 방안을 함께 제시해야 한다.
